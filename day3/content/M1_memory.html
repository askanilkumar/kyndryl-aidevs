2 · Two kinds of memory, two lifetimes

Short-term · the chat

Key: chat:<user>:<session> · Redis LIST · expires in minutes

Holds: the last N messages. Cheap to lose.

Long-term · the facts

Key: profile:<user> · Redis HASH · expires in weeks

Holds: name, city, plan, last ticket. Small, useful, deliberate.

⏱️ TTL: let Redis forget by itself

chat:cust-1001:default · TTL not set

4 · Where should we use this, and when should we NOT?



 
USE Redis memory for
   
  • session state and the last N messages
  • small facts about a customer
  • agent checkpoints (crash and resume)
  • anything that should expire

 
DO NOT use it for
   
  • the source of truth (use a database)
  • big documents (use the vector store from Day 2)
  • secrets, card numbers, raw phone numbers
  • data with no TTL and no owner
