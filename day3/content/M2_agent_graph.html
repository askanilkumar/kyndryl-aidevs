M2 · The agent and its graph

An agent is a loop: the model writes a plan → a guard checks it → we run a tool → the model reads the result. LangGraph draws that loop as boxes and arrows.

g.add_conditional_edges("act", route, {"observe": "observe"})
g.add_conditional_edges("observe", route, {"think": "think"})



Four ideas to keep



 
State
One dictionary: question, plan, observations, step, cost, phase. Everything the agent knows.

 
Checkpoint
Save the state after each box. A crash loses at most one box of work.

 
🛡️ Guard before action
Allow-list, "own account only", risky writes wait for a human.

 
Think before you move
The plan is visible and reviewable. If it cannot be explained, it cannot be trusted with a write.





Where should we use agents, and when should we NOT?



 
USE an agent when
  • the path depends on what the tools return
  • 2 to 5 tools, each with a clear job
  • a wrong answer is cheap, or a human approves

 
DO NOT when
  • the steps are always the same (write a normal function)
  • one RAG call answers it (RAG is enough)
  • there is no limit on cost, steps or permissions
