    Why put a gateway in front?
    
        
    • One endpoint and one API shape for every model.
    • Per-person keys with budgets and rate limits.
    • Real cloud keys stay on one machine.
    • Retries and fallbacks live in one place.
    • One log of who used what, and what it cost.
    
      
    When a gateway is the wrong tool
    
        
    • One app, one model, one developer. It is extra moving parts.
    • It becomes a single point of failure unless you run it twice.
    • It adds a hop. Fine for chat, relevant for tight latency budgets.
    • A badly set fallback can hide a quality drop. Log which model answered.
