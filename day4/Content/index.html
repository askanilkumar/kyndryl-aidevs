Cycle 1 — Memory

The one slide (talk against this, 10 min)

A plain chat call is stateless. The model knows nothing between calls. To make it feel like a conversation, YOU send the past turns every time. Those past turns are "memory".

Call 1"I am Anil"
No memoryCall 2 is a stranger
Add memorysend history each time
Cap itlast N or token budget

Where to keep it

Python dict (RAM)

Easy. Dies on restart. Not shared across workers. Fine for demos / tests.

Redis

Survives restarts. Shared. Same simple commands. Standard answer in production. Today we use fakeredis — same commands, no server to install.
Ask the trainee: in a web app with 4 Gunicorn workers, where does conversation memory have to live? Why?

Cycle 2 — Tool calling

The one slide (10 min)

The model cannot run anything. It only asks. Your code runs the tool. Your code sends the result back. The model reads it and writes the answer.

1you ask
2model asks for tool
3YOUR code runs it
4model writes answer

Three things to burn in:

  1. The model never executes code. It writes a request.
  2. You pick the schema (name, description, parameters). The description is how the model picks which tool.
  3. The tool_call_id on the way out must match on the way back — like a return address.
Ask the trainee: what happens if two parallel tool calls get the same id?

Cycle 4 — Agent loop

The one slide (10 min)

An agent is Lab 2, in a loop, with 3 safety rules.

loop:
    ask model (with tool menu)   <-- THINK
    if model asked for tools:
        run each one             <-- ACT
        send results back        <-- OBSERVE
        continue
    else:
        got the answer. STOP.
    stop also if step limit hit.

1. Step limit

Hard cap on rounds. No infinite bills.

2. Approval

Any write tool asks a human first.

3. Stop on repeat

Same tool, same args, twice → stop and hand over.
Ask the trainee: where does the approval check belong — in the prompt or in the code? Why?

Incident of the day — "AskNova is burning tokens on TKT-0004"

The CIO just pinged you. The agent has been "working on" one ticket for 5 minutes. Costs climbing.

  1. Switch the bug on: add ASKIT_INCIDENT=loop + ASKIT_MODEL=offline to .env.
  2. Run python run_agent.py "What is the status of ticket TKT-0004?". See get_ticket repeat until step limit.
  3. Fix: in agent.py set STOP_ON_REPEAT = True.
  4. Rerun. Should stop after 2 steps with "handing over to a human".
  5. Clean .env.

Lesson: step limit stops the loop, but after every step has been paid for. Repeat-detection stops the loop as soon as it starts. Both belong in production.
